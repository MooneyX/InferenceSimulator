# 功能状态与模块计划索引

本文只登记实施状态、依赖和详细计划的入口。现行行为以 [设计文档索引](../index.md) 及代码和测试为准；模块计划描述**尚未实施**的目标，不是现有 API 或性能保证。功能编号 `Fxxx` 保持稳定，完成状态只按已接通代码与测试更新。

## 功能状态与依赖

| 编号 | 能力 | 当前边界 | 依赖与后续计划 |
|---|---|---|---|
| `F003` | 完整块 ID 的前缀复用 | PC1–PC3A **L1 已完成**；单 Engine、一次性 Prefill；不包括低层、分块和解析模型 | 当前设计：[身份](../design/chunk-hash-encoding.md)、[L1](../design/kv-prefix-reuse.md)、[负载](../design/workload.md) |
| `F001` | 完整 token-level continuous batching | **待实现**；当前只有简化的动态准入/批大小变化 | 硬依赖 F003 的 L1 接口；[调度与引擎计划](scheduler-engine.md) |
| `F002` | 可配置、可解释和可校准的性能模型 | **待实现**；当前只有四系数经验模型 | 端到端集成硬依赖 F001 的 `StepWorkload`；公式/profile 可在接口冻结后并行开发；[性能模型计划](perf-model.md) |
| `KV3` | 多级 KV 缓存 | **待实现**；L2/L3 仅有配置和数据形状预留 | 依赖 L1 接口，不阻塞 F001；[KV 模块计划](kv-cache.md) |

```text
F003 L1（已完成） ──▶ F001 调度/引擎 ──▶ F002 端到端模型
           └────────▶ KV3 多级缓存（独立扩展）
```

F001 对 F003 的依赖是稳定的 block 级 probe/事务/发布/释放接口；其 chunked prefill、逐 chunk 发布及 retraction **编排属于 F001**。F002 的单步公式与配置可先行，但端到端验收须等待 F001 真实工作量。服务器和前端随各阶段交付，分别见 [服务/API 计划](server-api.md) 与 [前端计划](frontend.md)。

## 已完成阶段与范围边界

M1 内核入口、M2 同步服务/OpenAPI 类型生成、M3 表单/指标/Canvas 甘特图已落地；它们是已完成阶段的状态摘要，不构成今后每次变更的性能阈值。F003 的 L1 阶段在此基础上接入，不把 KV3、F001 或 F002 算作其完成条件。现行单 GPU、单 Engine 的范围不包括真实 KV tensor、跨实例/跨场持久化或 trace replay；`trace` 模式目前只预留接口。实时 WebSocket/单步、任务持久化和调度溯源 UI 尚未实现，不应在设计文档中描述为可用功能。

新增功能时更新本表和依赖图；具体字段、状态、算法、阶段验收仅写在对应的**负责模块**计划中。完成一个阶段后先核对代码和测试，再把已落地的稳定行为写入对应 `design/` 文档，并从该计划删去已完成的实施过程。
