# 前端配套实施计划

**状态：性能模型已统一，继续跟踪 F002/F004 后续页面工作。** 页面统一称为「性能模型」，不提供计时模式或四系数控件；导入直接拒绝旧 `inference.timing`，不自动转换。现行表单、三类结果与空态见 [前端设计](../design/frontend.md)；前端不自行推导调度或指标。下表保留阶段规划背景，经验/Roofline 切换不再是当前能力或待办。

| 前置模块 | 前端工作 | 验收 |
|---|---|---|
| [F004 第一阶段](expert-parallelism.md)、[F002 性能模型](perf-model.md) | 新增自定义模型/单卡硬件参数输入、预置版本、物理容量解析与经验/Roofline 计时切换；展示服务端返回的显存账单、有效 token 容量、规格来源和单步成本分项 | 前端不计算容量或 Roofline；缺参数/不支持的布局禁止自动运行；JSON 只接受统一 `SimConfig`，不接收冗余的 `inference.mode` 与 `shared_l3.mode`；Trace 导出清空临时 `plan_id`，导入需重新上传计划，未经校准值不标为实测 |
| [F004 第二、三阶段](expert-parallelism.md) | 随后补充 TP/EP 逐 rank 容量、通信和最慢 rank 展示 | 只显示已实现阶段及有数据的明细，不提前开放 DPA 或未经验证的模型组合 |

请求/响应类型继续从 OpenAPI 生成；每阶段同步配置默认值、错误处理和组件测试。`F002` 与 `F004` 的实施依赖由 [功能总览](feature-roadmap.md) 管理。
