分层 KV 缓存命中率从复用距离到恢复链路拥塞

缓存容量决定前缀能否留下，恢复带宽与运行时负载决定前缀能否被及时使用。以可解释模型和配对仿真数据，揭示 L1、L2、L3 命中率的变化规律与性能取舍。

HY4-Preview / MLA + DSABF16 · B300 配置闭环多轮会话解析仿真研究
核心问题　如何在命中收益与首 token 延迟之间选择合理配置？2026 年 10 月
摘要

三个结论，构成统一解释

研究对象是仿真系统中的前缀复用行为；下述数据不是实际硬件压测结果。

01 / 容量与复用窗口

L2 命中率呈单峰，而非越高越好

56.60%

基准配置在测试间隔中，于平均思考时间 550 秒达到最高 L2 命中贡献；更短间隔主要命中 L1，更长间隔转向 L3。

02 / 容量与带宽耦合

慢链路上，扩大 L3 可能反而更差

59.06→36.51%

L3 接入带宽 1 GB/s 时，容量由 2 TB 增至 8 TB，总命中率下降；8000 请求、思考 1750 秒，三种子均值。

03 / 指标与性能分离

高命中率也可能伴随严重排队

597.65 秒

L2 恢复带宽降至 2 GB/s 后，平均 TTFT 接近 600 秒，实际总命中仍约 79.54%。命中率不能替代延迟指标。

配置目标：不是最大化某一层命中率，而是在满足延迟要求的前提下，尽可能保留并及时恢复可复用前缀。

命中率：必须使用相同分母

hi = Hi / P，　H = h1 + h2 + h3si = hi / H，　η = (H1 + H2 + H3) / I

P 为成功请求总输入 token；Hi 为各层实际复用 token；I 为同一成功样本的理想可复用 token。hi 是命中贡献率，不是该层 lookup 成功率；si 是已命中 token 的层占比；η 表示实际捕获了多少理想复用。

性能与样本：避免错读

TTFT 为请求到达至首次 Prefill 完成的时间，表中报告平均值、单位秒。闭环完成吞吐受思考时间和尾部长度影响，不等于系统最大处理能力。

常规结果采用 seed = 0；标注“三种子”的结果使用 0、1、2 等权汇总，每次运行内部按输入 token 加权。更长时域使用 8000 请求、1600 会话，保持五轮结构与投放率不变。各表均明确样本规模与变量；不同分母的百分比不直接横比。

02

推导模型：从复用距离到层间分配

先解释容量宽裕、排队较轻时的主导规律，再加入运行时与链路约束。

模型 A / 静态近似

把缓存寿命换算成时间窗口

LRU 下，一个前缀能否保留，取决于两次复用之间经过的不同缓存页占用。将其粗略折算为 token 工作量：

D(t) ≈ λ C̄ tt1 = K1 / (λ C̄)t2 = (K1 + K2) / (λ C̄)K₁、K₂ 均为折算后的 KV token 容量，不能直接把 GB 与 token 相加。
λ
单实例请求率。基准名义值为 0.04 × 5 = 0.2 请求/s；拥塞时实际值未必达到该值。
C̄
平均输入上下文，基准约 17161 token。
t
父轮完成至子轮准入的复用间隔。轻排队时近似为思考时间。
t < t₁前缀仍在 L1
t₁ < t < t₂前缀转移至 L2
t > t₂需要 L3 或重新计算

D 的线性近似会重复计入同一会话的访问，不是精确的不同页复用距离；边界用于解释趋势，不是逐请求的确定性判定。

模型 A / 指数思考时间

L2 是两个边界之间的概率质量

设平均思考时间为 T，对指数分布积分，得到可复用前缀落在各窗口中的近似比例：

p1 = 1 − e−t₁/Tp2 = e−t₁/T − e−t₂/Tp3 = e−t₂/Tp₃ 表示低于 L2 的恢复需求；只有 L3 保留且能成功恢复时，才转化为 L3 实际命中。

对 p₂ 关于 T 求导并令其为零：

T* = (t2 − t1) / ln(t2 / t1)

基准 L1 = 9254 页、L2 = 39939 页，折算为 592256 与 2556096 token；t₁ ≈ 173 秒、t₂ ≈ 917 秒，简化模型的连续峰值 T* ≈ 446 秒。测试档位中的 L2 峰值在 550 秒；峰值高度需由数据检验，不能由近似式精确保证。

数据验证 A

模型解释单峰，但会低估部分区间的 L2 层占比

容量与负载能解释曲线方向，不能独立解释所有幅度。

  • 短间隔下 L1 留存更充分，模型高估不同页复用距离，因而高估早期 L2 占比。
  • T = 550 秒时，模型 L2 占比约 54.3%，仿真约 71.2%；定性单峰成立，峰值高度明显不同。
  • T ≥ 1750 秒时，约 4T 的会话思考时长与约 20000 秒名义投放时域可比，有限时域不能视作充分稳态。
五轮会话的理想命中率约为 79.55%。1 − 1/轮数只能作粗估；新增 token、页对齐和输入加权都会改变精确比例。

03

容量与负载：决定命中窗口的位置

这一组规律适用于恢复带宽宽裕、运行压力较轻的配置；不能无条件外推到拥塞区。

数据验证 B

增大 L2，主要延后向 L3 溢出的边界

T = 100 秒时四档均约 7.1%；T = 1000 秒时则为 15.3%、29.4%、50.2%、65.3%。缓存尚未溢出时，增加低层容量几乎没有收益。

数据验证 C

L1 越小，前缀越早落到 L2，但也压缩运行请求所需的 KV 空间。215 GB 档在不同思考时间下的平均 TTFT 为 9–42 秒，260 GB 档约为 2.5–2.7 秒。

L2 命中率提高，可能只是命中从更快的 L1 下移，而不是更多计算被省掉。

负载的三种等效变化：只在近似条件下成立

04

恢复链路：命中是否可用的第二道约束

“页还在缓存里”与“请求能够及时用上该页”是两件事。

模型 B / 有效容量与等待

标称 L1 容量，不等于可淘汰缓存容量

K1,eff(t) = K1 − A1(t) − I1(t)treuse = tthink + twaitA₁：运行中请求占用、且不含在途占位的受保护 KV；I₁：在途目的占位。两者不重复计数，单位均为 token 等价量。

更慢的计算、Decode 或恢复链路，既延长请求等待，也使活动 KV 与传输保护占用维持更久。因此，静态模型中的容量和间隔都会改变。

恢复流量上升
→
排队与占位增加
→
可用缓存减少

这是一组机制解释，不是已经校准的动态闭式预测器。在途来源保护、部分预取与重新计算之间的反馈，不能用单一容量比例充分描述。

模型 B / 恢复需求与服务能力

带宽必须覆盖有固定开销的逐页服务

q2 ≈ λC̄b(h2 + h3)， q3 ≈ λC̄bh3τj = ℓj + bB / Wjρj ≈ [qj / (bB)] · τjb：整组 KV 字节/token；B：页 token 数；W：链路字节/s；ℓ：每页固定秒数；q：字节/s。ρ 为近似负载强度，不是实测利用率。

用低压力配置的 h 估算需求。ρ 接近 1 时应关注突发与排队；ρ 小于 1 也不能保证低延迟。该近似忽略重复传输、重算反馈与时间非平稳性，不把拥塞后的低命中率代回公式来“证明”链路稳定。

基准 b = 801216 字节/token。T = 550 / 1750 秒时，估算 L2 恢复需求约 1.59 / 1.93 GB/s，L3 约 0.035 / 0.907 GB/s。
数据验证 D

L2 带宽下降：延迟先恶化，总命中并非同步下降

2 GB/s 时，命中贡献大量转向 L3；总命中约 79.54%，但平均 TTFT 已达 597.65 秒。单看命中指标会漏掉恢复瓶颈。
数据验证 E · 三种子

容量 × 带宽：同样的扩容，可能走向完全不同的结果

8000 请求、1600 会话、T = 1750 秒、L1 = 260 GB、L2 = 2048 GB、L2 → L1 = 256 GB/s；改变 L3 容量与 L3 → L2 带宽。三种子均值；括号为三次结果最小–最大值，不是置信区间。

关键观察：8 TB + 1 GB/s 不但比 2 TB + 1 GB/s 延迟更高，总命中也更低；将带宽提高到 4 GB/s 后，总命中恢复至约 79.21%，平均 TTFT 为 4.38 秒。三个种子均呈现这一方向。

更长运行时域会暴露累积拥塞

表 6 · L3 = 8 TB，其余同上；每会话 5 轮、投放率 0.04/s，三种子均值。请求数 4000 → 8000 对应名义会话投放时域约 20000 → 40000 秒，实际总时长还包含等待及会话尾部。

较长运行不是“稳态已收敛”的证明。尤其在瓶颈附近，必须保留时域条件，不能把短时域结果外推到持续运行。
05

运行时因素：为何相同容量会得到不同命中率

计算、上下文增长、并行布局与预取策略，分别改变活动占用、复用上限或恢复需求。

数据验证 F

HBM 与并发相互影响：降低并发不一定“腾出缓存”

4000 请求、T = 550 秒、有效算力 100 TFLOPS；仅改变 HBM 有效带宽和最大运行并发，其余为基准。

HBM = 500 GB/s 时，最大并发从 8 增至 32，平均 TTFT 从约 3006 秒降至 6.11 秒；L1 贡献也从 1.54% 升至 13.40%。并发限制、吞吐和请求在系统内的驻留时间共同决定缓存压力。

数据验证 G

长输出与上下文增长的联合影响远大于各自影响

4000 请求、T = 550 秒，P/D 分步、Prefill 额度 16384 token；改变 Poisson 输出均值与每轮新增长度均值。

输出 512 + 新增 4096 时，平均 TTFT 达 1756.10 秒。此时理想命中率也改变，必须同时比较“实际 / 理想”捕获比例，而不能把不同负载的总命中率直接当作缓存效率排名。
数据验证 H

预取门槛：少恢复与多重算之间的取舍

表 9 · 4000 请求、T = 1750 秒、L3 = 40 TB，其余基准。门槛单位 token；总命中率对总输入加权。

慢链路下适度提高门槛，可以同时减少排队和改善实际复用；门槛高于当前可复用前缀时，L3 贡献为零。快链路上如此抑制预取反而显著增加延迟。

数据验证 I

大页：摊薄固定开销，牺牲页尾复用

表 10 · 4000 请求、T = 1750 秒，L2/L3 每页固定延迟均设为 10 ms，其余为基准。各档理想命中率随页对齐改变。

页从 64 增至 1024 token 时，平均 TTFT 从 8.33 秒降至 3.14 秒；理想命中率同时由约 79.55% 降至 77.59%。性能收益并不等于更多 token 得到复用。

06

结论：用两类约束指导容量与性能判断

先估算复用窗口，再核对恢复能力和运行时占用；同时看命中贡献与延迟。

容量约束

前缀能否保留？

统一换算为 token 或页容量，扣除权重、预留与活动占用。使用 λC̄T 与有效容量的相对大小，定位 L1 主导、L2 主导和 L3 需求区。

服务约束

保留的前缀能否及时取回？

按低压力命中分配估算逐链路流量，并计入每页固定开销。扩大低层缓存时同步评估恢复需求，避免容量收益被排队抵消。

统计约束

观察窗口是否足够？

明确请求数、会话结构、随机种子和投放时域。瓶颈附近的结果应同时报告较长时域表现，而不是仅给出一次短运行的高命中率。

最终判断

分层命中率由复用距离、有效容量、恢复服务能力与运行时反馈共同决定。静态模型能解释主要趋势；在拥塞区域，容量更大、L2 命中更高或并发更低，都不必然意味着更好的端到端体验。

边界

如何使用这些结论

保留必要的实验条件与不确定性，避免把仿真结论误作实际部署承诺。

结论支持的范围

  • 针对 HY4-Preview 结构、给定有效硬件参数、BF16 与合成闭环会话的解析仿真；配置数值不代表 B300 实际测量。
  • 容量与带宽关键对照的三种子结果给出了均值与极值范围；其余主要为 seed = 0，不能据小幅变化推断普遍显著性。
  • 所有百分比均按说明的分母计算。实际与理想命中只在同一成功样本上比较；完整组合实验没有请求失败或跳过。
  • 表中毫秒输入已统一换算为秒，GB/TB 采用十进制。L1 为每卡含权重预算，L2 为单实例整组 KV，L3 为共享总量。

模型没有覆盖的现实因素

  • 固定 LRU；本地 L1/L2 为迁移而非长期备份；不支持跨会话公共前缀，思考时间采用指数分布。
  • 每实例每条恢复链路串行，两条链路与 GPU 可以重叠；未模拟共享 L3 的全局带宽竞争，下行降级不计写回耗时。
  • L3 没有淘汰也不保证理想复用全部实现：在途保护、目的占位和部分预取均可能影响准入。内部原因的精确贡献比例未被量化。
  • 未覆盖 FP8 的专门量化布局；8000 请求也不等于已经验证稳态收敛。恢复服务时长之和不能直接加到总完成时间。
