01请求到达 P

匹配本地 L1 / L2 连续前缀；对未命中部分按条件提交异步 L3 查询与 L3→L2 预取。

并行接收

01请求到达 D

独立匹配 D 的 L1 / L2 / L3 前缀，确定本地已有或可恢复的 KV。

02进入 bootstrap_queue

等待 D 发布目标信息；P 的 L3 预取在后台继续，不要求先读完才能入队。

各自推进

02传输前准入

检查请求行与 KV 预算；为 P 未命中的后缀预分配 GPU 接收地址，也为 D 本地前缀恢复留出空间。

03进入 waiting_queue

收齐 D 的目标信息并取得交接信息槽位后，离开 bootstrap_queue。

← 目标地址与前缀长度

03通知 P

发送接收地址与 decode_prefix_len；被 D 命中的 L2 / L3 前缀将由 D 自行恢复。

04Prefill 组批

跳过未达到 L3 预取停止条件的请求；按队列顺序、请求行、KV 容量和 token / chunk 预算选取请求。

并行推进

04D 本地前缀恢复

L3 命中先进入 D 的 L2；需要使用时再由 L2 载回 D GPU。

05执行 Prefill

将所需 P L2 KV 载回 GPU，并计算剩余 prompt。长 prompt 可以分多个 chunk。

中间 chunk 可更新 L1 radix 前缀，但通常不触发新 Full-KV 的写穿备份。
计算 / 恢复可重叠

05等待后缀 KV

继续恢复 D 本地前缀；D 不会重复接收 decode_prefix_len 覆盖的部分。

06最终 chunk 就绪

对 prompt KV 进行非 chunked 缓存插入，符合条件时触发 P GPU→P L2 的写穿备份。

P→D KV 传输与 P 的 HiCache 备份是独立路径。
KV：P GPU → D GPU →

06接收 KV

P 可提前发送已完成的中间 chunk；D 接收缺失的 KV 后缀，不必等待 P 将 prompt 写入 L3。

07PD 交接完成

最终 KV 和辅助信息发送成功后，P 释放该请求占用的资源；本地异步备份可继续。

首 token 等辅助信息 →

07接收与恢复汇合

P 传来的后缀和 D 自行恢复的前缀均就绪，请求才进入 D 的 waiting_queue。

08P 异步写共享 L3

P L1→L2 写入确认后，再提交 L2→共享 L3 写入；L3 完成之前不能算作可用命中。

独立缓存任务

08PREBUILT

首次 Decode 前将已提交的 prompt KV 插入 D radix；符合条件时，D 也可能启动 prompt 写穿备份。

09P 处理其他请求

已经完成写入的 P 侧 L3 前缀可供后续请求查询，尚在途的写入则不可用。

持续并行

09运行 Decode

取得运行空位并满足下一步 KV 容量后逐 token 生成；通常不会每生成一个 token 就写穿。

10共享前缀逐步可用

P 对子请求重新匹配自己的 L1 / L2，并仅查询共享 L3 中已完成写入的前缀。

共享 L3

10Decode 结束

尝试插入新增的可缓存输出 KV，触发 D GPU→D L2→共享 L3 的异步备份。

11子请求复用

当共享 L3 写入完成、缓存键和 KV 布局兼容时，子请求可预取父请求的 KV 前缀。

L3 写入完成后可命中

11输出前缀可共享

D 的 L2→L3 写入确认后，新增的可缓存输出 KV 才能作为后续请求的共享 L3 命中。

仿真边界：省略失败、取消、回撤和特殊模型路径。缓存插入、L2 备份完成、L3 写入完成是三个不同事件； P 的 Prefill 完成、PD 传输完成、D 的 Decode 完成也不是同一时点。D 的 PREBUILT 备份保留在图中，简化实现时可作为可选事件。
