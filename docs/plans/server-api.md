# 服务与 API 配套计划

**状态：跟踪 F002 与 F004 尚未交付的服务工作。** 当前 F001/KV3 API、状态与错误码见 [服务设计](../design/api.md)，此处不重复已实现契约。

| 前置模块 | 服务与 schema 交付 | 验收 |
|---|---|---|
| [F004 第一阶段](expert-parallelism.md)、[F002 性能模型](perf-model.md) | 接收自定义模型/硬件规格或固定版本预置；服务端调用同一纯容量解析过程，在负载规划及引擎启动前形成唯一 `engine.max_total_tokens`，回显显存账单、来源和有效配置；分别接入旧经验计时和按步 Roofline 解析计时 | 同输入与规格快照可复现；无有效 KV 布局或显存不足明确拒绝；旧路由与旧计时不变；解析步成本有可核对分项 |
| [F004 第二、三阶段](expert-parallelism.md) | 在第一阶段解析入口扩展逐 rank TP/EP 放置、容量与通信成本契约；每阶段同步对外 schema | TP 与 EP 按阶段分别验收，不提前开放未经验证的模型或后端组合 |

任何对外配置或路由调整均以 `core.schemas` 为事实源，重新生成并提交 `web/openapi.json`、`web/src/api/schema.d.ts`；服务层不另造同名数据模型，不把未实现的后端选项加入可选择的产品配置。UI 接入与字段说明见 [前端计划](frontend.md)。
