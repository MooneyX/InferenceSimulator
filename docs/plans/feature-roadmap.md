# 功能状态与模块计划索引

本文只登记实施状态、依赖和详细计划的入口。现行行为以 [设计文档索引](../index.md) 及代码和测试为准；模块计划描述**尚未实施**的目标，不是现有 API 或性能保证。功能编号 `Fxxx` 保持稳定，完成状态只按已接通代码与测试更新。

## 功能状态与依赖

| 编号 | 能力 | 当前边界 | 依赖与后续计划 |
|---|---|---|---|
| `F003` | 完整块 ID 的前缀复用 | PC1–PC3A **L1 已完成**；单 Engine、一次性 Prefill；不包括低层、分块和解析模型 | 当前设计：[身份](../design/chunk-hash-encoding.md)、[L1](../design/kv-prefix-reuse.md)、[负载](../design/workload.md) |
| `F001` | 单实例连续调度主干 | **待实现**；默认 P/D 互斥，可切换同一步融合；两模式共用逐请求准入、按进度分配和回撤；chunked prefill 后续扩展 | [调度与引擎计划](scheduler-engine.md) |
| `F002` | 可配置、可解释和可校准的性能模型 | **待实现**；当前只有四系数经验模型 | 端到端集成硬依赖 F001 的 `StepWorkload`；公式/profile 可在接口冻结后并行开发；[性能模型计划](perf-model.md) |
| `KV3` | 多级 KV 缓存 | **待实现**；L2/L3 仅有配置和数据形状预留 | 首期 F001 不依赖 KV3；KV3 实现时需对接改造后的 L1 接口；[KV 模块计划](kv-cache.md) |

```text
F003 L1（已完成） ──▶ F001 调度/引擎 ──▶ F002 端到端模型
                          └────────▶ KV3 多级缓存（适配新版 L1）
```

F001 使用完整块身份与连续前缀命中，统一以逐请求预算、按进度分配和 retraction 管理两种 P/D 模式；默认互斥，可配置为同一步融合。chunked prefill 与逐 chunk 发布列为后续扩展。F002 的单步公式与配置可先行，端到端验收依赖 F001 的实际阶段工作量。服务器和前端随各阶段交付，分别见 [服务/API 计划](server-api.md) 与 [前端计划](frontend.md)。

## 已完成阶段与范围边界

现行 M1 内核、M2 服务/OpenAPI 类型链、M3 表单和甘特图是已实现入口；F001 交付以两种 P/D 模式共用的新缓存与调度契约为准。单 GPU、单 Engine 范围不包括真实 KV tensor、跨实例持久化或 trace replay；实时单步、任务持久化和调度溯源 UI 不属于本期。

新增功能时更新本表和依赖图；F001 的字段、状态、算法和验收统一以 [调度与引擎实施规范](scheduler-engine.md) 为准，其他计划仅列模块交付边界。完成 F001 后同步设计文档的已实现状态，不删除或重新定义本规范。
